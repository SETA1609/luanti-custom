# zig-luanti migration checklist

CMake → Zig build-system migration. Branch: `zig-build-system`.
CMake remains the canonical build until Phase 14 deletes it.

## How to read this file

Each phase has:
- A checkbox marker — `[x]` done, `[~]` partially done (deliberately), `[ ]` outstanding.
- A **What** section — the concrete deliverable.
- A **How** section — the build steps / files / decisions, so anyone can pick the phase up cold.
- Sub-bullets where one phase covers several deps or sub-tasks.

Per the [commit workflow memory](../.claude/memory/feedback-commit-workflow.md), every phase commit also flips its `[ ]` → `[x]` here so the file stays current.

## Phases

### [x] Phase 0 — Scaffolding

**What:** Empty `build.zig` + `build.zig.zon` that pin Zig 0.16.0 and name the fork.

**How:**
- `build.zig`: `pub fn build(b: *std.Build) void` that does nothing.
- `build.zig.zon`: `.name = .zig_luanti`, `.version = "5.17.0-dev"`, `.fingerprint = 0xd78c9f8fe7c68bf` (do not change), `.minimum_zig_version = "0.16.0"`, no deps yet.
- `.gitignore` gains `.zig-cache/`, `zig-out/`, `zig-pkg/`.
- `zig build` exits 0; CMake build is untouched.

### [x] Phase 1 — Options + generated headers

**What:** Every CMake option exposed as `-D...`; `cmake_config.h` and `cmake_config_githash.h` generated byte-compatibly by Zig.

**How:**
- `build_options.zig` — `Options.parse(b, ...)` calls `b.option(...)` for every flag in `CMakeLists.txt` / `src/CMakeLists.txt` (build-client/server/unittests, run-in-place, all `enable-*` deps, custom install dirs).
- `build_config.zig` — `VERSION_*` constants, `ConfigProbes.detect(os_tag)` (HAVE_ENDIAN_H, …), `renderCmakeConfigH(...)` which mirrors `src/cmake_config.h.in` line for line.
- The git-hash header is generated by `b.runAllowFail({"git","rev-parse","--short","HEAD"})` at build-script time; missing-repo is tolerated.
- Both headers land under `zig-out/include/` and are made available to downstream targets via `addWriteFiles`.

### [x] Phase 2 — Small vendored libs

**What:** `lib/jsoncpp`, `lib/sha256`, `lib/tiniergltf`, `lib/gmp`, `lib/bitop` build as static libs (or a Module, in tiniergltf's header-only case).

**How:**
- `build_lib.zig` introduces the single reusable `addVendorLib(b, target, optimize, spec)` helper and the `VendorLib` spec struct.
- Each lib is described inline in `build.zig` with one literal — no per-lib wrapper functions.
- `sha256` needs an `endian.h` probe; we synthesize its tiny per-lib `cmake_config.h` from `ConfigProbes.have_endian_h`.
- `bitop` builds only when `!use_luajit` (LuaJIT has `bit32` built in).
- `tiniergltf` is exposed as `b.addModule("tiniergltf", …)` and gets `addIncludePath` for both `lib/tiniergltf` and `lib/jsoncpp` (it `#include <json/json.h>`).

### [x] Phase 3 — Vendor Lua 5.1.4

**What:** `lib/lua/src/*.c` builds as static lib `lua`, compiled as C++ (upstream does the same).

**How:**
- 28 source files (`lapi.c` … `lzio.c`) listed in `lua_sources` in `build.zig`.
- `VendorLib.language = .cpp` forces clang to treat the `.c` files as C++.
- Platform-conditional flags: `LUA_USE_POSIX` + `LUA_USE_DLOPEN` on Linux, `LUA_USE_MACOSX` on Darwin, `LUA_BUILD_AS_DLL` on Windows, else `LUA_ANSI`.
- Public headers (`lua.h`, `lauxlib.h`, `lualib.h`, `luaconf.h`) installed via `installHeader`.
- Skipped when `-Duse-luajit=true` (LuaJIT replaces it whole).

### [x] Phase 4 — Foundation deps (zlib / zstd / sqlite3)

**What:** Three foundational C libs fetched via Zig's package manager, hash-pinned in `build.zig.zon`.

**How:**
- `zig fetch --save=zlib git+https://github.com/allyourcodebase/zlib#1.3.2`
- `zig fetch --save=zstd git+https://github.com/allyourcodebase/zstd#1.5.7-1`
- `zig fetch --save=sqlite3 git+https://github.com/allyourcodebase/sqlite3`
- `b.dependency(name, .{ .target, .optimize }).artifact(...)` for each; install + named step.
- Artifact names: `zlib`→"z", `zstd`→"zstd", `sqlite3`→"sqlite3".

### [x] Phase 5 — EngineCommon static library

**What:** The 73 .cpp files Luanti's engine compiles into a single static lib shared by client and server (CMake's `EngineCommon OBJECT` lib).

**How:**
- `build_engine.zig::common_sources` enumerates them: `independent_SRCS` (src/CMakeLists.txt:420-449) + the PARENT_SCOPE lists from `src/util/`, `src/threading/`, `src/content/`, `src/database/`, `src/network/` (common bits only).
- Compiled at `-std=c++17 -fno-strict-aliasing -DUSE_CMAKE_CONFIG_H`. Engine sources include `<cmake_config.h>` from `generated.getDirectory()` (LazyPath from Phase 1).
- `linkLibrary` on every vendored dep propagates include paths.
- Defaults flipped so the engine compiles out of the box: `enable-curl/gettext/sound/curses/postgresql/leveldb/redis/prometheus/spatial/openssl` all default to `false` during the migration.
- `-fno-sanitize=undefined` added to per-file flags so Zig's Debug UBSan doesn't trap the engine's float-to-int casts (CMake doesn't enable UBSan by default; this matches behavior).

### [x] Phase 6 — `luantiserver` executable — **VALIDATION GATE 1** ✓

**What:** End-to-end server build, links + runs, reports correct version.

**How:**
- `build_engine.zig::server_sources` (108 files: common_SRCS direct + mapgen + script_common + common_server + server_network) compiled into the exe module.
- `lib/lstrpack` vendored as a sibling C lib (single .c file; Lua 5.3 `string.pack` backport).
- `MT_BUILDTARGET=2` set on the exe (gates client branches in `src/main.cpp` via `src/config.h:40-49`).
- System libs: `-ldl -lrt` on Linux, `-lpthread` on BSDs, `ws2_32/shlwapi/winmm/version` on Windows.
- Gate proof: `zig-out/bin/luantiserver --version` reports `Luanti 5.17.0-dev-debug-<hash>-dirty (Linux) ...`.

### [x] Phase 8 — IrrlichtMt static library

**What:** The in-tree IrrlichtMt fork builds as `libIrrlichtMt.a` (~78 MB Debug), linkable by the client.

**How:**
- `build_engine.zig::irr_sources` lists the 60 .cpp files from the 5 OBJECT libs (IRRMESHOBJ, IRRVIDEOOBJ, IRRIOOBJ, IRROTHEROBJ, IRRGUIOBJ) plus IrrlichtMt's own scene-node sources.
- Backend selection: SDL2 windowing + legacy GL + GL3 unified backend (Linux desktop default). GLES2 / EGL skipped until Android / Emscripten phases.
- `irr_cxx_flags_linux`: `-std=gnu++17` (not `c++17` — `CFileSystem.cpp` errors on `__STRICT_ANSI__`), `-fno-strict-aliasing`, `-fno-sanitize=undefined`, `_IRR_POSIX_API_`, `_IRR_COMPILE_WITH_SDL_DEVICE_`, `_IRR_COMPILE_WITH_JOYSTICK_EVENTS_`, `_IRR_COMPILE_WITH_OPENGL_`, `ENABLE_OPENGL3`.
- Include wiring: `irr/include` (PUBLIC) + `irr/src` (PRIVATE) + `sdl_dep.path("include")` + `sdl_dep.path("include-pregen")` (for `SDL_config.h`) + `lib/tiniergltf` + `lib/jsoncpp` + `src/` (for `util/base64.h`).
- `linkLibrary` for zlib / libjpeg / libpng / SDL2 propagates their installed headers.

### [x] Phase 9 — `luanti` (client) executable — **VALIDATION GATE 2** (partial)

**What:** Client builds, links, and starts. Full gameplay validation still pending.

**How:**
- `build_engine.zig::client_only_sources` = 99 client-only .cpp files (`src/client/`, `src/gui/`, `src/irrlicht_changes/`, `src/network/client*`, `src/script/scripting_{client,mainmenu,pause_menu,sscsm}.cpp`, `src/script/cpp_api/s_client*` + s_mainmenu/s_pause_menu/s_sscsm, `src/script/lua_api/l_camera/l_client*` etc., `src/script/sscsm/`).
- Client exe module compiles `server_sources + client_only_sources` (`common_SRCS` is included by both targets in CMake) with `MT_BUILDTARGET=1`.
- Links every vendored lib including IrrlichtMt, freetype, libpng, libjpeg, SDL2.
- Linux system libs: `-ldl -lrt -lGL`. Windows adds `opengl32`.
- Data dirs (`builtin/`, `fonts/`, `client/shaders/`, `textures/base/pack/`, `games/`, `clientmods/`, `client/serverlist/`) installed under `zig-out/share/luanti/` so `porting::setSystemPaths()` finds them via the `<bindir>/../share/luanti` trypath.
- Gate proof so far: `./zig-out/bin/luanti --version` runs cleanly. Mainmenu still blocked on the SDL2 X11/Pulse archive-member linker issue (see Phase 7 notes — passing the right SDL flags through `b.dependency("sdl", ...)` is the open task).

### [ ] Phase 10 — Catch2 + unit tests + benchmarks

**What:** `zig build test` runs the engine's existing test suite (`src/unittest/`) and benchmark suite (`src/benchmark/`).

**How:**
- Vendor `lib/catch2` as a static lib (single amalgamated TU works fine).
- Wire `src/unittest/*.cpp` + `src/test/*.cpp` + `src/catch.cpp` into the executables when `build_unittests=true`.
- Wire `src/benchmark/*.cpp` when `build_benchmarks=true`.
- Add a top-level `b.step("test", ...)` that builds + runs the resulting binary with the existing `--run-tests` argument convention.
- Flip the default of `build_unittests` back to `true` to match CMake.
- *Note:* commit `b596661e3` already laid the Catch2 + C-ABI groundwork; this phase finishes it.

### [ ] Phase 11 — Windows cross-compile

**What:** `zig build -Dtarget=x86_64-windows-gnu` and `-Dtarget=x86_64-windows-msvc` produce working `luanti.exe` + `luantiserver.exe`.

**How:**
- Confirm every vendored dep (jsoncpp, gmp, sha256, bitop, lua, libpng, libjpeg, freetype, SDL2, mbedTLS, curl, zlib, zstd, sqlite3, IrrlichtMt) cross-builds cleanly under both ABIs.
- Translate the windres / `.rc` resource compile in `src/CMakeLists.txt:510-527` — Zig ships its own resource compiler.
- Add `_WIN32_WINNT=0x0601`, `WIN32_LEAN_AND_MEAN`, MSVC vs MinGW compile flag branches matching `src/CMakeLists.txt:288-300, 904-936`.
- Confirm `target.result.os.tag == .windows` branches in `build.zig` (already exist for system libs).

### [ ] Phase 12 — macOS `.app` bundle

**What:** `zig build -Dtarget=aarch64-macos` (and `x86_64-macos`) produces a working `Luanti.app` bundle.

**How:**
- After the link step, an install rule constructs `Luanti.app/Contents/{MacOS,Resources}/`.
- Translate `misc/macos/Info.plist.in` substitution (versions, bundle id) via a Zig `WriteFile` step.
- Confirm IrrlichtMt's `_IRR_OSX_PLATFORM_` define and the `GL_SILENCE_DEPRECATION` flag are set; map `_IRR_POSIX_API_` correctly.
- LTO stays off on Darwin (known IrrlichtMt crash on ARM64 — see `CMakeLists.txt:53-59`).

### [ ] Phase 13 — Android shared library

**What:** `zig build -Dtarget=aarch64-linux-android` (and `x86_64-linux-android`) produces `libluanti.so` consumed by the existing Gradle project.

**How:**
- Switch the client target type from executable to `.dynamic`-linkage shared lib when targeting Android.
- Define `_IRR_ANDROID_PLATFORM_`; switch IrrlichtMt to GLES2 backend (`ENABLE_GLES2=true`, drop `ENABLE_OPENGL3`).
- Update `android/app/build.gradle` to call `zig build` instead of `externalNativeBuild`. APK assembly stays in Gradle.

### [ ] Phase 14 — Remove CMake

**What:** Delete all `CMakeLists.txt`, `cmake/`, and `*.cmake.in` files; Zig becomes the canonical build.

**How:**
- Remove all 29 `CMakeLists.txt` files, `cmake/Modules/`, `src/cmake_config.h.in`, `src/cmake_config_githash.h.in`, `cmake/Modules/GenerateVersion.cmake`.
- Update `README.md` "Compiling" section to reference `zig build`.
- Replace CMake-based CI workflows under `.github/workflows/` with `zig build` invocations.
- Delete the `build/` entry in `.gitignore` (no longer relevant).
- This is the point where the migration is complete and the CMake reference comparison ends.

### [ ] Phase 15 — Modernize engine sources to C++23

**What:** Engine compiles cleanly at `-std=c++23`. No `-fno-sanitize=undefined` workaround.

**How:**
- Bump `cxx_flags` in `build_lib.zig`, `build_engine.zig`, and the inline server/client flag arrays from `c++17` to `c++23`.
- Walk the resulting compile errors file by file with focused commits. Known categories:
  - Add `#include <iterator>` wherever `std::inserter` is used (no longer transitive in C++23).
  - Replace `std::cout << wchar_t` with explicit casts or `std::wcout`.
  - Replace deprecated `std::result_of` / `std::is_pod` if any appear.
- Drop the `-fno-sanitize=undefined` flag once the underlying UB (e.g. `irr/src/CGUIScrollBar.cpp:285` float→int cast) is fixed.
- Stay scoped to language-standard breakage — do NOT adopt new features (`ranges`, `std::format`, `consteval`) in this phase; that's a separate refactor.

### [ ] Phase 16 — Clone `main.cpp` to `main.zig` (final post-migration)

**What:** Translate ONLY the entry-point (`src/main.cpp`) into Zig. The rest of the engine stays C++ and is called via `extern "C"` adapters.

**How (do NOT start until Phase 15 ships):**
- Identify the 5-8 entry points `main.cpp` calls into (likely `run_dedicated_server`, `ClientLauncher::run`, `MainMenu::run`, `init_log_streams`, `read_config_file`, …).
- Add `src/entry_abi.{h,cpp}` exposing each as `extern "C"` — narrow, stable signatures.
- Replace `src/main.cpp` with `src/main.zig`. Arg parsing, logging setup, error-typed dispatch with `defer`/`errdefer` for cleanup choreography.
- Add a tiny `src/main_stub.c` holding `int main(int, char**)` that forwards to `luanti_main` (so the linker has a `main` symbol when the Zig module emits `pub fn main()`).
- Approximate scope: 400-800 lines of Zig + ~200 lines of C++ wrappers, replacing ~600 lines of `main.cpp`.
- Validation: both binaries still launch with identical CLI behavior vs. the CMake reference (which is gone by now — diff against the pre-Phase-14 git tag).

**Why this late?** Doing it before Phase 15 means rewriting both sides of the hourglass when C++23 changes ABI / API expectations of the engine. Doing it after means the Zig side targets a stable, modernized C++23 engine and the translation is final. Commit `b596661e3` did an initial pass of this work; the final clone should review that as a starting point but assume nothing about it is keepable.

## Notes

- This file is the single source of truth for phase status. The rest of the build documentation in `FORK.md` just points here.
- Every phase commit ends with one focused commit on `zig-build-system`, pushed to `origin` immediately so progress is recoverable.
- Optional engine features (`enable-curl`, `enable-leveldb`, …) default to `false` during the migration; they flip back to CMake's `true` defaults as their vendored deps land in Phase 7 / Phase 9 (and `enable-curl` was reverted to `false` to dodge a temporary curl link issue).
- The `main.cpp` entry point stays canonical through Phase 15. Phase 16 is the only phase that touches `src/main.{cpp,zig}` in the final layout — the `main.zig` work in commit `b596661e3` is parked groundwork, not the final translation.
